# ClipBucket — sandbox / development notes

Legacy PHP app (ClipBucket 4.2, Apache + mod_php, MySQL, Smarty templates).
The web root is **`upload/`** — not the repository root.

## Run

```bash
docker compose -f docker-compose.base44.yml up -d --build   # http://localhost:3000
```

Services: `db` (MySQL 5.7), `install` (one-shot provisioner), `web` (Apache on :80 →
host :3000). `web` waits for `install` to exit successfully.

## Non-obvious things

- **PHP 7.4 is required.** The code base targets PHP 5–7 (`split()`, zero dates,
  `create_function` era code) and breaks on PHP 8. The image is
  `php:7.4-apache-bullseye`; bullseye is archived, so the Dockerfile rewrites
  `sources.list` to `archive.debian.org`.
- **Mount point matters.** `ClipBucket::getBasedir()` derives `BASEDIR` from
  `dirname(__FILE__)` by stripping `includes`/`classes` and the last two
  characters, so `upload/` must be mounted exactly at `/var/www/html`.
- **MySQL 5.7 with `--sql-mode=NO_ENGINE_SUBSTITUTION`.** The seed data contains
  `'0000-00-00 00:00:00'` dates that MySQL strict mode rejects.
- **Installation is scripted.** The shipped installer (`upload/cb_install`) is a
  multi-step browser wizard. `docker/install.php` performs the same steps
  (structure → configs → ads_placements → countries → email_templates → pages →
  user_levels → categories → admin → config values → `includes/langs/en.lang`
  phrases) from the CLI and is idempotent (exits early when `cb_config` has rows).
  It also **deletes `files/temp/install.me`** — while that marker exists,
  `check_install('after')` forces the site into "closed" mode and every page only
  shows the "We Are Updating Our Website" notice.
- `upload/includes/dbconnect.php` and `upload/includes/clipbucket.php` are
  generated by the installer and git-ignored.
- The site's `baseurl` lives in the `config` table. In the sandbox the preview
  origin changes per environment, so `upload/includes/common.php` derives it from
  `BASE44_PUBLIC_HOST_SUFFIX` **only when `BASE44_PREVIEW_MODE=1`**; unset, the
  stored `baseurl` is used unchanged.
- Directories the web server writes to (`files/`, `images/`, `styles/`, `cache/`,
  `player/`, `includes/email_templates/`) are `chmod`ed by the `web` command on
  start (`a+rwX`, so repository file modes are preserved).
- Video conversion binaries (ffmpeg, flvtool2, MP4Box) are **not** installed:
  the site browses/renders fine, but uploaded videos are never converted.
- **Signup needs `email_verification = 0`.** There is no mail transport in the
  sandbox, so with verification on every new account would sit at "check your
  email" forever. `docker/install.php` seeds it off; turn it back on in
  `admin_area` once SMTP is configured.

## Admin

`/admin_area/login.php` — `admin` / `admin` (seeded by the installer).

## Verify

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/          # 200
curl -s http://localhost:3000/ | grep -c "Recent Videos"                  # 1
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/admin_area/login.php
```

A healthy homepage is ~20 KB and contains `<body`; if it shrinks to ~9 KB and
shows the "We Are Updating Our Website" notice, `files/temp/install.me` is back.
